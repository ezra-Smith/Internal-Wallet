## 功能概述

`pkg/secrets` 是一个统一的密钥管理包，支持：

- ✅ **本地开发**：从 `.env` 文件加载密钥
- ✅ **生产环境**：从 AWS Secrets Manager 加载密钥
- ✅ **自动环境检测**：根据配置文件的 `Mode` 字段自动选择密钥源
- ✅ **类型安全**：强类型配置结构
- ✅ **全局缓存**：密钥加载后缓存在内存中
- ✅ **密钥验证**：生产环境强制密钥强度检查

## 核心特性

### 1. 多密钥源支持

| 环境 | 密钥源 | 触发条件 |
|------|--------|---------|
| 本地开发 | `.env` 文件 | `Mode: dev` 或 `APP_ENV=local` |
| 测试环境 | AWS Secrets Manager | `Mode: test` 或 `APP_ENV=dev` |
| 预发环境 | AWS Secrets Manager | `Mode: pre` 或 `APP_ENV=staging` |
| 生产环境 | AWS Secrets Manager | `Mode: pro` 或 `APP_ENV=production` |

### 2. 自动项目根目录查找

系统会自动向上查找包含 `.env` 或 `go.mod` 的目录（最多 10 层），无论从哪个子目录启动服务都能正确加载。

### 3. 密钥验证

| 环境 | 验证策略 |
|------|---------|
| 本地开发 (`local`) | 宽松验证（只检查必填项，弱密码仅警告） |
| 生产环境 (`production`/`staging`) | 严格验证（密码长度、强度要求） |

**生产环境密钥要求：**
- Signer 加密密码：≥ 32 字符
- MySQL 密码：≥ 16 字符
- Redis 密码：≥ 16 字符
- JWT 密钥：≥ 32 字符
- Admin JWT 密钥：≥ 32 字符

```bash

```

```bash

# 生成 JWT 密钥（48 字节）

# 生成 Signer 加密密钥（32 字节，极其重要！）
```

## 使用方法

### 方式 1：从配置文件 Mode 加载（推荐）⭐

**特点：** 无需配置环境变量，自动根据 YAML 配置的 `Mode` 字段选择密钥源。

#### 配置文件示例

```yaml
# services/business/rpc/etc/business.yaml
Name: business.rpc
Mode: dev  # 👈 关键：决定密钥源

# MySQL 配置（密码留空，自动从 secrets 包注入）
MySQL:
  Host: localhost
  Password: ""  # 占位符
```

#### 服务代码

```go
// services/business/rpc/business.go
package main

import (
    "context"
    "internalwallet/pkg/secrets"
    "github.com/zeromicro/go-zero/core/conf"
)

func main() {
    flag.Parse()
    ctx := context.Background()

    // 方式 1：从配置文件 Mode 自动加载（推荐）
    secretConfig, err := secrets.LoadFromConfigMode(ctx, *configFile)
    if err != nil {
        panic(err)
    }

    var c config.Config
    conf.MustLoad(*configFile, &c)

    // 注入密钥到配置
    c.MySQL.Password = secretConfig.Database.MySQL.Password
    c.Redis.Host = secretConfig.Cache.Redis.Address()  // 返回 "host:port"
    c.Redis.Password = secretConfig.Cache.Redis.Password
    c.JWT.AccessSecret = secretConfig.Security.JWT.AccessSecret

    // 启动服务...
}
```

#### Mode 映射关系

```go
// pkg/secrets/loader.go
Mode: dev   → 环境: local       → 密钥源: .env 文件
Mode: test  → 环境: dev          → 密钥源: AWS (crypto-wallet/dev/config)
Mode: pre   → 环境: staging      → 密钥源: AWS (crypto-wallet/staging/config)
Mode: pro   → 环境: production   → 密钥源: AWS (crypto-wallet/production/config)
```

---

### 方式 2：使用 APP_ENV 环境变量（向后兼容）

**特点：** 显式指定环境，适用于特殊场景。

#### 设置环境变量

```bash
# 本地开发
export APP_ENV=local

# 生产环境
export APP_ENV=production
export AWS_REGION=us-east-1
```

#### 服务代码

```go
// 方式 2：使用 APP_ENV 环境变量
secretConfig, err := secrets.Load(ctx)
if err != nil {
    panic(err)
}
```

#### 优先级

如果同时存在配置文件 `Mode` 和环境变量 `APP_ENV`：

```
方式 1（推荐）：LoadFromConfigMode() → 读取 YAML Mode → 忽略 APP_ENV
方式 2（兼容）：Load()                → 读取 APP_ENV → 如果未设置，默认 "local"
```

## 环境变量配置

### 必需环境变量（本地开发 .env 文件）

| 变量名 | 描述 | 示例值 | 最小长度 |
|--------|------|--------|---------|
| `MYSQL_HOST` | MySQL 主机地址 | `localhost` | - |
| `MYSQL_PORT` | MySQL 端口 | `15306` | - |
| `MYSQL_USERNAME` | MySQL 用户名 | `crypto` | - |
| `MYSQL_PASSWORD` | MySQL 密码 | `crypto123456` | 16 字节（生产）|
| `MYSQL_DATABASE` | 数据库名称 | `crypto_wallet` | - |
| `REDIS_HOST` | Redis 主机 | `localhost` | - |
| `REDIS_PORT` | Redis 端口 | `6379` | - |
| `REDIS_PASSWORD` | Redis 密码 | `redis123456` | 16 字节（生产）|
| `JWT_ACCESS_SECRET` | JWT Access 密钥 | `生成的 Base64 密钥` | 32 字节 |
| `JWT_REFRESH_SECRET` | JWT Refresh 密钥 | `生成的 Base64 密钥` | 32 字节 |
| `ADMIN_JWT_ACCESS_SECRET` | Admin JWT Access | `生成的 Base64 密钥` | 32 字节 |
| `ADMIN_JWT_REFRESH_SECRET` | Admin JWT Refresh | `生成的 Base64 密钥` | 32 字节 |
| `SIGNER_ENCRYPTION_PASSWORD` | **Signer 主密钥** | `生成的强密钥` | 32 字节 ⚠️ |

### 可选环境变量

| 变量名 | 描述 | 默认值 |
|--------|------|--------|
| `KAFKA_BROKERS` | Kafka 地址（逗号分隔） | `localhost:9092` |
| `SMTP_HOST` | 邮件服务器 | `smtp.gmail.com` |
| `SMTP_PORT` | 邮件端口 | `587` |
| `AWS_REGION` | AWS 区域 | `us-east-1` |

### ⚠️ 特别警告

**`SIGNER_ENCRYPTION_PASSWORD` 是最关键的密钥！**
- 用于加密主种子（BIP39 mnemonic）
- 丢失此密钥将导致所有钱包永久无法恢复
- 生产环境必须：
  - 使用强随机密钥（≥ 32 字节）
  - 安全备份到多个位置
  - 使用密钥管理服务（AWS KMS/Vault）

### Kubernetes 部署（非 AWS）

**密钥源：** Kubernetes Secret

**步骤 1：创建 Secret**

```bash
kubectl create secret generic app-secrets \
  --from-literal=MYSQL_PASSWORD=$(cat .env | grep MYSQL_PASSWORD | cut -d'=' -f2) \
  --from-literal=REDIS_PASSWORD=$(cat .env | grep REDIS_PASSWORD | cut -d'=' -f2) \
  --from-literal=JWT_ACCESS_SECRET=$(cat .env | grep JWT_ACCESS_SECRET | cut -d'=' -f2) \
  -n crypto-wallet
```

**步骤 2：Deployment 配置**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: business
spec:
  template:
    spec:
      containers:
      - name: business
        image: your-registry/business:latest
        env:
        - name: APP_ENV
          value: "local"  # 使用 K8s Secret（不走 AWS）
        - name: MYSQL_PASSWORD
          valueFrom:
            secretKeyRef:
              name: app-secrets
              key: MYSQL_PASSWORD
        - name: REDIS_PASSWORD
          valueFrom:
            secretKeyRef:
              name: app-secrets
              key: REDIS_PASSWORD
        # ... 其他密钥
```

**配置文件：**

```yaml
# etc/business.yaml
Mode: dev  # 或通过 APP_ENV=local
```

```json
      "Effect": "Allow",
      "Action": [
        "secretsmanager:GetSecretValue",
        "secretsmanager:DescribeSecret"

        "arn:aws:secretsmanager:us-east-1:123456789012:secret:crypto-wallet/production/*"
```

```yaml

  name: business

      - name: business
        image: your-registry/business:latest
        env:

        - name: APP_ENV
          value: "production"  # 触发 AWS Secrets Manager
        - name: AWS_REGION
          value: "us-east-1"

```


## API 参考

### 主要函数

#### `Load(ctx context.Context) (*SecretConfig, error)`

从环境变量 `APP_ENV` 加载密钥（如果未设置，默认 `local`）。

```go
secretConfig, err := secrets.Load(ctx)
```

#### `LoadFromConfigMode(ctx context.Context, configPath string) (*SecretConfig, error)` ⭐

从配置文件的 `Mode` 字段加载密钥（**推荐方式**）。

```go
secretConfig, err := secrets.LoadFromConfigMode(ctx, "etc/business.yaml")
```

#### `LoadWithMode(ctx context.Context, mode string) (*SecretConfig, error)`

使用指定的 Go-Zero Mode 加载密钥。

```go
secretConfig, err := secrets.LoadWithMode(ctx, "pro")
```

#### `LoadWithEnv(ctx context.Context, env string) (*SecretConfig, error)`

使用指定环境名称加载密钥。

```go
secretConfig, err := secrets.LoadWithEnv(ctx, "production")
```

#### `MustLoad(ctx context.Context) *SecretConfig`

加载密钥，失败则 panic（适用于 main 函数）。

```go
secretConfig := secrets.MustLoad(ctx)
```

### 配置结构

#### `SecretConfig`

```go
type SecretConfig struct {
    Version     string
    Environment string
    LastUpdated time.Time

    Database      DatabaseConfig
    Cache         CacheConfig
    Messaging     MessagingConfig
    Security      SecurityConfig
    Notifications NotificationConfig
    Monitoring    MonitoringConfig
}
```

#### 获取 Redis 地址

```go
// 对于 Go-Zero CacheRedis（需要 "host:port" 格式）
redisAddr := secretConfig.Cache.Redis.Address()
// 返回：localhost:6379

// 对于其他框架（分离的 host 和 port）
host := secretConfig.Cache.Redis.Host     // localhost
port := secretConfig.Cache.Redis.Port     // 6379
```

## 故障排查

### 问题 1：.env 文件加载失败

**症状：**
```
ℹ️  .env file not found at /path/to/.env, using environment variables only
```

**原因：**
- `.env` 文件不存在
- 文件路径不正确

**解决方案：**

```bash
# 1. 检查文件是否存在
ls -la .env

# 2. 检查当前目录
pwd

# 3. 从项目根目录运行服务
cd /path/to/Internal-Wallet
cd services/business/rpc
go run business.go
```

**自动查找逻辑：** 系统会向上查找 10 层目录，通常无需担心路径问题。

---

### 问题 2：AWS Secrets Manager 连接失败

**症状：**
```
❌ Failed to load secrets: failed to get secret crypto-wallet/production/config: AccessDeniedException
```

**原因：**
- IAM 权限不足
- Secret 名称错误
- 区域配置错误

**解决方案：**

```bash
# 1. 检查 AWS 凭证
aws sts get-caller-identity

# 2. 检查 Secret 是否存在
aws secretsmanager get-secret-value \
  --secret-id crypto-wallet/production/config \
  --region us-east-1

# 3. 检查 IAM 权限
aws iam get-role-policy \
  --role-name crypto-wallet-role \
  --policy-name secrets-access
```

---

### 问题 3：密钥验证失败

**症状：**
```
❌ configuration validation failed: CRITICAL: signer encryption password must be at least 32 characters (got 16)
```

**原因：** 生产环境使用了弱密码

**解决方案：**

```bash
# 生成强密钥（32 字节 = 44 字符 Base64）
openssl rand -base64 32

# 更新 .env 或 AWS Secrets Manager
SIGNER_ENCRYPTION_PASSWORD=生成的密钥（44字符）
```

---

### 问题 4：Redis 连接失败 "missing port"

**症状：**
```
redis: connection pool: failed to dial: address localhost: missing port in address
```

**原因：** RPC 服务需要 `host:port` 格式，但配置只有 `host`

**解决方案：**

```go
// ✅ 正确：使用 Address() 方法
if len(c.CacheRedis) > 0 {
    c.CacheRedis[0].Host = secretConfig.Cache.Redis.Address()  // localhost:6379
    c.CacheRedis[0].Pass = secretConfig.Cache.Redis.Password
}

// ❌ 错误：只传 Host
c.CacheRedis[0].Host = secretConfig.Cache.Redis.Host  // localhost（缺少端口）
```

---

### 问题 5：Linux 上 .env 文件不加载

**症状：** Linux 上运行服务，.env 文件存在但未加载或加载信息不显示

**原因：**
- 文件权限问题
- Windows 换行符（CRLF）导致解析失败
- 路径问题
- 输出被重定向

**快速诊断：**

```bash
# 运行测试脚本
go run scripts/test-secrets-loading.go
```

**解决方案：**

```bash
# 1. 检查文件权限
ls -la .env
# 应该是 -rw-r--r-- 或 -rw-------

# 2. 转换 Windows 换行符为 Unix 换行符
dos2unix .env
# 或者使用 sed
sed -i 's/\r$//' .env

# 3. 检查文件格式
cat -A .env | head -5
# 应该只看到 $ 符号，没有 ^M

# 4. 修复文件权限
chmod 644 .env

# 5. 从项目根目录启动
cd /path/to/Internal-Wallet
make run-business
```

**详细故障排查指南：** 请参阅 [Linux故障排查.md](./Linux故障排查.md) 获取完整的诊断和解决方案。

## 最佳实践

### 1. 密钥生成

**✅ 推荐：**

```bash
# 使用 OpenSSL 生成强随机密钥
openssl rand -base64 32  # 32 字节（MySQL、Signer）
openssl rand -base64 48  # 48 字节（JWT，更强）
```

**❌ 避免：**

```bash
# 弱密码
MYSQL_PASSWORD=123456
SIGNER_ENCRYPTION_PASSWORD=password

# 可预测密码
JWT_ACCESS_SECRET=my-secret-key
```

---

### 2. 环境隔离

**本地开发：**
```yaml
Mode: dev → .env 文件 → 弱密码 OK（警告）
```

**预发环境：**
```yaml
Mode: pre → AWS staging → 强密码要求
```

**生产环境：**
```yaml
Mode: pro → AWS production → 严格密码验证
```

---

### 3. 密钥轮换

**JWT 密钥轮换（每 90 天）：**

```bash
# 1. 生成新密钥
NEW_KEY=$(openssl rand -base64 48)

# 2. 更新 AWS Secrets Manager
aws secretsmanager update-secret \
  --secret-id crypto-wallet/production/config \
  --secret-string "$(jq '.security.jwt.access_secret = "'"$NEW_KEY"'"' secrets.json)"

# 3. 滚动重启服务
kubectl rollout restart deployment/business -n crypto-wallet
```

**Signer 密钥：永不轮换！** 丢失将导致所有钱包无法恢复。

---

### 4. 备份策略

**Signer 加密密钥备份：**

```bash
# 1. 加密备份
echo "SIGNER_ENCRYPTION_PASSWORD=xxx" | \
  gpg --encrypt --recipient admin@company.com > signer-key.gpg

# 2. 多地存储
- 密钥管理系统（Vault/KMS）
- 离线硬件安全模块（HSM）
- 加密 USB 存储（异地保管）
- 纸质备份（保险柜）
```

```json
{
  "Effect": "Allow",
  "Action": [
    "secretsmanager:GetSecretValue"  // 只读权限
  ],
  "Resource": [
    "arn:aws:secretsmanager:us-east-1:123456789012:secret:crypto-wallet/production/config"  // 仅特定 Secret
  ]
}
```

## 常见问题 (FAQ)

### Q1: 本地开发必须配置 .env 吗？

**A**: 是的，本地开发需要 `.env` 文件。如果没有，服务会尝试从环境变量读取，但通常会因为缺少必需密钥而启动失败。

---

### Q2: 生产环境必须使用 AWS Secrets Manager 吗？

**A**: 不一定。生产环境可以选择：
- AWS Secrets Manager（AWS EKS 推荐）
- HashiCorp Vault
- Kubernetes Secret（非 AWS 环境）
- 自建密钥管理系统

只需设置 `APP_ENV=local` 并通过环境变量注入密钥即可。

---

### Q3: 如何在不重启服务的情况下更新密钥？

**A**: 当前实现不支持热更新。密钥在服务启动时加载并缓存。更新密钥需要重启服务。

**未来改进方向：**
- 监听 AWS Secrets Manager 版本变更
- 提供 `/reload-secrets` 管理接口
- 支持密钥过期自动轮换

---

### Q4: `.env` 文件会被提交到 Git 吗？

**A**: 不会。`.env` 已在 `.gitignore` 中。只有 `.env.example` 模板会被提交。

---

### Q5: 如何验证密钥是否正确加载？

**A**: 查看服务启动日志：

```bash
# 成功日志示例
✅ .env file loaded from /path/to/.env
✅ [SECRETS] Loaded from local .env (environment: local)
Secrets loaded successfully (environment: local)

# 或 AWS 加载
📦 Fetching secret: crypto-wallet/production/config
✅ [SECRETS] Loaded from AWS Secrets Manager (environment: production)
```
